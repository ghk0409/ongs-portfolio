04 / DATA INTEGRITY실무 · 현장 자재 관리

N:M 연결과 FIFO로 재고 계산의 정합성 지키기

공유 소비량을 한 번만 계산하고, 잔량과 품목 상태가 같은 입고 이력에서 나오도록 계산 모델을 보완했습니다.

ROLE재고 계산 도메인·조회 API·회귀 테스트 구현
TECHNOLOGYPython · FastAPI · MySQL · pytest
SOURCE코드 비공개
ON THIS PAGE
01 Overview02 Problem03 Constraints04 Architecture / Decision05 Implementation06 Result07 Retrospective
01OVERVIEW

무엇을 만들었나

하나의 자재 저장소가 여러 사용처에 연결되고, 사용처도 여러 저장소를 공유하는 N:M 구조의 사료 관리 기능을 다뤘습니다. 입고·반품·예상 소비를 바탕으로 잔량과 소진 상태를 계산하는 도메인과 API를 보완했습니다.

02PROBLEM

어떤 문제가 있었나

공유 사용처의 소비를 중복 계산하거나 남은 총량을 저장소 용량 비율로 다시 나누면 비어 있던 저장소에 재고가 생기는 결과가 나올 수 있었습니다. 이미 소진된 입고 품목이 혼합 상태에 남는 문제도 있었습니다.

03CONSTRAINTS

무엇을 바꿀 수 없었나

실측 재고가 아니라 표준 사용량과 업무 이력에 따른 예상값이었습니다. N:M 연결, 부분 출하, 입고·반품 날짜와 기존 응답 계약을 함께 유지해야 했고, 정수 단위로 나눠도 합계가 어긋나지 않아야 했습니다.

04ARCHITECTURE / DECISION

어떤 경계를 선택했나

연결된 저장소와 사용처를 그룹으로 묶어 소비량을 한 번만 계산했습니다. 차감 전의 양수 잔량을 배분 가중치로 사용하고, 정수 나머지는 largest-remainder 방식과 고정된 동률 규칙으로 처리했습니다. 총 잔량과 품목 상태는 입고 lot의 FIFO 잔량에서 함께 도출했습니다.

05IMPLEMENTATION

어떤 책임을 구현했나

연결 그룹 계산, 실제 차감 가능량 제한, half-up 단위 변환과 안정적인 입고 순서를 구현했습니다. 소비와 부분 반품은 오래된 lot부터 차감하고 전체 반품은 lot을 초기화했습니다. 부분 출하·사용 기간 경계, 미입고 저장소의 경고와 반품 조회도 보완했습니다.

06RESULT

무엇이 확인됐나

직접 작성한 변경에서 배분 합계 보존, 0 잔량의 재생성 방지, 소진 품목의 혼합 표시 제거를 확인했습니다. N:M 반례, 초과 소비, 날짜 경계와 같은 날의 입고 순서를 다루는 회귀 테스트가 코드에 포함돼 있습니다. 실제 재고 정확도 개선율은 측정 성과로 주장하지 않습니다.

07RETROSPECTIVE

무엇을 다시 고려하나

총량이 맞는 것만으로 재고 모델이 맞다고 볼 수 없었습니다. 품목·이력·사용처별 해석도 일치해야 했습니다. 예상 재고와 실측 재고의 차이를 드러내고, 반품이 어느 입고 lot에 귀속되는지 더 명시적인 입력 계약으로 만드는 것이 다음 과제입니다.
