04 / AI SYSTEM개인 공개 프로젝트

AIRS — AI 작업을 검증 가능한 계약과 정책으로

작업 계약부터 라우팅, 정책 검사와 실행 기록까지 연결했습니다.

01OVERVIEW

무엇을 만들었나

AIRS는 저장소의 규칙과 작업 상태를 기준으로 AI 개발 작업을 계획·실행·검증하는 로컬 오케스트레이터입니다. AI 도구가 무엇을 했는지보다 어떤 근거로 실행을 허용하고 기록할지를 설계했습니다.

02PROBLEM

어떤 문제가 있었나

여러 AI 도구를 쓰는 작업에서는 지시가 대화창에 흩어지고, 위험한 작업과 단순한 작업이 같은 경로로 실행되기 쉽습니다. 나중에 왜 특정 도구·검토 수준을 선택했는지 재구성하기도 어렵습니다.

03CONSTRAINTS

무엇을 바꿀 수 없었나

저장소의 문서와 코드가 작업의 기준이어야 했고, 명확한 작업까지 매번 무거운 판단 과정을 거치게 할 수 없었습니다. 도구별 CLI 차이를 수용하면서도 실행 권한과 검증 기준은 하나의 정책으로 통제해야 했습니다.

04ARCHITECTURE / DECISION

어떤 경계를 선택했나

작업을 YAML/JSON Task Contract로 구조화했습니다. 분명한 작업은 Rule Router가 결정하고, 애매한 작업은 별도 평가 결과를 받아도 Policy Engine이 최소 검토 수준과 가드레일을 최종 적용합니다. 실행 도구는 어댑터 뒤에 두고, 결정·명령·결과를 작업별 이력으로 남깁니다.

05IMPLEMENTATION

어떤 책임을 구현했나

plan, run, review, verify, status CLI 흐름과 계약 스키마, 라우팅·정책, Codex·agy CLI 어댑터, dry-run 및 이력 저장을 구현했습니다. 테스트는 외부 평가 호출을 모킹하고 실행 계획을 검증하도록 구성했습니다.

06RESULT

무엇이 확인됐나

공개 저장소의 v0.3.2 기준으로 작업 계약부터 라우팅, 정책 검사, 실행 기록까지 한 경로로 확인할 수 있습니다. 현재는 로컬 우선 참조 구현이며, 실제 시간 절감·품질 개선 같은 성과는 측정하지 않았습니다.

07RETROSPECTIVE

무엇을 다시 고려하나

AI 활용의 핵심은 모델 선택보다 범위, 위험, 검증 책임을 코드로 남기는 것이었습니다. 운영 수준으로 발전시키려면 이력 보존·민감정보 제거, 라우팅 평가와 도구 실패 복구를 더 강화해야 합니다.
