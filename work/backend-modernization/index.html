08 / MODERNIZATION실무 · 커머스 데이터 서비스

서비스를 유지하며 백엔드 구조를 점진적으로 전환하기

Express 유지보수와 NestJS 도입을 함께 진행하며, 기존 응답 계약·공통 트랜잭션·외부 요청 처리와 상품 추적 테스트를 정리했습니다.

01OVERVIEW

무엇을 만들었나

커머스 데이터 서비스의 기존 Express 백엔드를 유지보수하면서 NestJS 기반 신규 서버의 구조와 공통 모듈을 개발했습니다. 신규 기능 구현과 기존 코드 이관, 테스트 추가 및 배포 환경 구축을 함께 맡았습니다.

02PROBLEM

어떤 문제가 있었나

기존 서버의 요구사항과 배치 크롤링 오류를 처리하는 한편, 신규 서버에서는 기능별 책임과 반복되는 처리를 정리해야 했습니다. 상품 추적 기능에는 등록 한도·중복 검사도 필요했고, 신규 구현의 응답을 기존 서비스가 사용하는 형태에 맞춰야 했습니다.

03CONSTRAINTS

무엇을 바꿀 수 없었나

기존 서비스 유지보수와 신규 기능 개발을 함께 진행했습니다. 신규 기능부터 NestJS를 도입하되 기존 응답 형태를 맞추는 DTO와 인터셉터를 구현했으며, 기존 코드의 이관도 별도 작업으로 진행했습니다.

04ARCHITECTURE / DECISION

어떤 경계를 선택했나

도메인 기반의 헥사고날·클린 아키텍처를 바탕으로 신규 구조를 만들고, 외부 HTTP·트랜잭션·예외·응답 처리를 공통 모듈로 구성했습니다. 트랜잭션 데코레이터는 실행 문맥의 EntityManager를 연결했고, 기존 응답 계약은 DTO·인터셉터에서 맞췄습니다. CQRS는 검토했지만 서비스와 개발팀 상황을 고려해 보류했습니다.

05IMPLEMENTATION

어떤 책임을 구현했나

axios 외부 요청 모듈, 트랜잭션 데코레이터·문맥 연결, 공통 오류 필터와 응답 인터셉터를 개발했습니다. 상품 추적 서비스에 등록 한도·사용자별 중복 검사를 추가하고 관련 Jest 테스트를 작성했습니다. 기존 코드 이관과 GitLab 빌드–테스트–배포, 후속 AWS CodePipeline 환경 구축 및 VPC·ECS/ECR·CodeDeploy·CloudWatch, 서버·배치 이관 작업에도 참여했습니다.

06RESULT

무엇이 확인됐나

기존 응답 형태를 맞추는 DTO·인터셉터와 신규 백엔드의 공통 처리 기반을 구현했습니다. 상품 추적의 등록 한도·중복 검사와 서비스 테스트를 추가하고 코드 이관·배포 기반 작업을 진행했습니다.

07RETROSPECTIVE

무엇을 다시 고려하나

지금 다시 보면 이 경험의 핵심은 새 프레임워크의 도입보다 기존 기능과 신규 구조를 함께 다루는 일이었습니다. 모든 패턴을 도입하기보다 팀과 서비스 상황에 맞춰 적용 범위를 정하는 판단도 중요합니다. 다음에는 이관 대상별 완료 조건과 회귀 검증 결과를 기록해 전환의 진행 상태를 더 명확히 설명하고 싶습니다.
