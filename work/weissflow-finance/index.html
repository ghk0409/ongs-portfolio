WF / 02 / FINANCIAL SYSTEMWeissflow · 금융 도메인

가상 원장과 시장 알림을 연결하는 검증 경계

원장 변경, 알림 전달, 시뮬레이션의 책임을 나누고 상태를 바꾸는 지점을 백엔드에 모았습니다.

ROLE도메인·백엔드 설계 및 웹 연동
TECHNOLOGYNestJS · PostgreSQL · Next.js · SSE · Kubernetes
SOURCE소스 비공개
ON THIS PAGE
01 Overview02 Problem03 Constraints04 Architecture / Decision05 Implementation06 Result07 Retrospective
01OVERVIEW

무엇을 만들었나

가상 투자 지갑과 자산 원장, 시장 감시 피드, 백테스트와 몬테카를로 위험 분석을 개발했습니다. 여러 분석 결과를 사용자에게 전달하되 실제 투자 성과나 실제 주문 실행과 혼동하지 않도록 구현 범위를 구분합니다.

02PROBLEM

어떤 문제가 있었나

알림과 분석 결과는 원장의 현재 상태와 다른 시점에 만들어질 수 있습니다. 화면에서 잔고를 따로 계산하거나 알림을 곧바로 주문으로 처리하면 상태 불일치와 중복 변경이 생길 수 있습니다.

03CONSTRAINTS

무엇을 바꿀 수 없었나

외부 시세와 뉴스의 지연·실패를 수용해야 합니다. 현재 브로커는 내부 모의 모드이며 실제 주문은 잠겨 있습니다. 백테스트에는 외부 이력 조회 실패 시 합성 시계열을 사용하는 경로가 있어 결과의 데이터 출처를 함께 다뤄야 합니다.

04ARCHITECTURE / DECISION

어떤 경계를 선택했나

가상 투자 상태 변경은 백엔드 트랜잭션으로 처리하고, 모니터링 결과는 저장한 뒤 SSE로 전달합니다. 사용자 행동은 별도 API에서 검증합니다. 백테스트·위험 분석은 원장 변경과 별도 계산 서비스로 두고, 웹 스튜디오에서 입력 조건과 결과를 살펴보게 했습니다.

05IMPLEMENTATION

어떤 책임을 구현했나

가상 매수·매도·환전과 배치 리밸런싱, 모니터링 피드 및 Next.js SSE 전달 경로를 구현했습니다. 정기 실행에는 중복 실행 방지 설정을 적용했습니다. 이후 다중 조건 규칙, 환율 분할 매수 계획, 백테스트와 몬테카를로 분석 서비스 및 대응하는 웹 스튜디오를 추가했습니다.

06RESULT

무엇이 확인됐나

원장·피드·계산 서비스와 웹 화면을 잇는 구현 경로가 마련돼 있습니다. 백테스트와 스트레스 테스트는 분석 기능으로 소개하며 수익률·예측 정확도·운영 효과를 실적처럼 제시하지 않습니다.

07RETROSPECTIVE

무엇을 다시 고려하나

분석 결과의 재현성을 높이려면 데이터 출처와 기준 시각, 합성 데이터 사용 여부, 난수 조건을 결과와 함께 기록해야 합니다. 원장 일관성과 분석의 타당성은 각각의 검증 항목으로 유지할 필요가 있습니다.
