03 / OPERATIONS실무 · 스마트 축산 운영 플랫폼

설비 배치와 센서 이력을 잇는 운영 대시보드

설비·MQTT 매핑과 공간 좌표, 다중 센서·시계열을 화면이 사용할 수 있는 응답 계약으로 연결했습니다.

ROLE현장 데이터·설비 배치·대시보드 API 구현
TECHNOLOGYPython · FastAPI · MySQL · ClickHouse · SSE · MQTT
SOURCE코드 비공개
ON THIS PAGE
01 Overview02 Problem03 Constraints04 Architecture / Decision05 Implementation06 Result07 Retrospective
01OVERVIEW

무엇을 만들었나

현장 운영자가 시설 상태를 확인할 수 있도록 설비 배치와 MQTT 장비 매핑, 다중 센서 값과 업무 데이터를 연결하는 백엔드 API를 개발했습니다. 공간 좌표와 상태를 포함한 응답으로 설비 시각화 화면과 운영 대시보드의 접점을 구성했습니다.

02PROBLEM

어떤 문제가 있었나

데이터의 발생 주기와 저장 위치가 달라 한 화면에서 함께 보기 어려웠습니다. 실시간에 가까운 값과 누적 이력을 같은 방식으로 취급하면 지연·누락·오래된 값을 사용자가 구별하기 힘들었습니다.

03CONSTRAINTS

무엇을 바꿀 수 없었나

현장 장비와 네트워크 상태를 백엔드가 통제할 수 없고, 일부 데이터는 시계열 저장소에 있었습니다. 사용자는 접근 권한이 있는 현장 데이터만 보아야 했습니다.

04ARCHITECTURE / DECISION

어떤 경계를 선택했나

현재 상태, 이력 조회와 실시간 전달을 구분하고 설비 배치·장비 연결·값의 신선도를 따로 모델링했습니다. 공간 좌표는 비율 좌표와 실제 치수를 구분하고, 환기 추세는 현재 상태를 과거에도 적용하지 않고 시간별 작동 이력을 사용하도록 보완했습니다.

05IMPLEMENTATION

어떤 책임을 구현했나

설비 배치·MQTT 장비 매핑 API, 실측 기반 3D 좌표, 다중 센서 배열과 전체 구역 조회를 구현했습니다. 설비 수량이 줄 때 배치·매핑의 고아 데이터를 보정하고, 시간별 환기 이력과 동시간 음수량 비교의 기준을 수정했습니다. 영상 온라인 상태는 SSE 구독 여부에 따라 폴링 대기를 조절했습니다.

06RESULT

무엇이 확인됐나

직접 작성한 API·DTO·서비스와 테스트에서 설비·센서·업무 데이터의 통합 응답, 배치·장비 연결 정합성 및 시계열 조회 보완을 확인했습니다. 이 사례의 기여 범위는 백엔드 연동과 응답 계약이며 3D 렌더러나 예측 모델 전체를 직접 만든 것으로 설명하지 않습니다.

07RETROSPECTIVE

무엇을 다시 고려하나

실시간은 전송 방식의 이름이 아니라 데이터의 신선도를 사용자에게 정확히 설명하는 계약입니다. 화면에서 값의 시간·출처·접근 범위를 함께 표현해야 신뢰 가능한 운영 도구가 됩니다.
