03 / OPERATIONS실무 · 스마트 축산 운영 플랫폼

센서·영상·업무 데이터를 잇는 운영 모니터링

값의 신선도와 접근 범위를 함께 전달하는 API 흐름을 만들었습니다.

ROLE현장 데이터 API 및 실시간 전달 흐름 구현
TECHNOLOGYPython · FastAPI · PostgreSQL · InfluxDB · WebSocket
SOURCE코드 비공개
ON THIS PAGE
01 Overview02 Problem03 Constraints04 Architecture / Decision05 Implementation06 Result07 Retrospective
01OVERVIEW

무엇을 만들었나

현장 운영자가 시설 상태를 확인할 수 있도록 센서, 영상, 평가·재고 등의 업무 데이터를 연결하는 백엔드 기능을 개발했습니다.

02PROBLEM

어떤 문제가 있었나

데이터의 발생 주기와 저장 위치가 달라 한 화면에서 함께 보기 어려웠습니다. 실시간에 가까운 값과 누적 이력을 같은 방식으로 취급하면 지연·누락·오래된 값을 사용자가 구별하기 힘들었습니다.

03CONSTRAINTS

무엇을 바꿀 수 없었나

현장 장비와 네트워크 상태를 백엔드가 통제할 수 없고, 일부 데이터는 시계열 저장소에 있었습니다. 사용자는 접근 권한이 있는 현장 데이터만 보아야 했습니다.

04ARCHITECTURE / DECISION

어떤 경계를 선택했나

현재 상태, 이력 조회, 실시간 전달의 책임을 분리했습니다. 시계열 데이터의 시간 의미를 API 응답에 드러내고, 영상·센서·업무 데이터의 접근 범위는 도메인 권한 정책과 연결했습니다.

  1. 현장 장비
  2. 시계열·업무 데이터
  3. 상태·이력 API
  4. 운영 화면
05IMPLEMENTATION

어떤 책임을 구현했나

센서 이력과 최신 상태 조회, 실시간 갱신 경로, 영상 접근 및 운영 지표 API를 구현했습니다. 누락·지연 상황에서 값의 시각과 상태를 구분할 수 있도록 응답을 정리했습니다.

06RESULT

무엇이 확인됐나

서로 다른 현장 데이터를 운영 화면에서 함께 사용할 수 있는 백엔드 접점을 마련했습니다. 실제 지연 시간이나 장애 개선 수치는 공개 가능한 측정값이 없어 제시하지 않습니다.

07RETROSPECTIVE

무엇을 다시 고려하나

실시간은 전송 방식의 이름이 아니라 데이터의 신선도를 사용자에게 정확히 설명하는 계약입니다. 화면에서 값의 시간·출처·접근 범위를 함께 표현해야 신뢰 가능한 운영 도구가 됩니다.
