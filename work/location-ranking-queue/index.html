01OVERVIEW

무엇을 만들었나

위치 기반 리뷰·기록 서비스의 도메인과 백엔드를 개발하고, 순위 알고리즘 및 Redis Queue 기반 후처리를 구현했습니다. 회사 실무이며 개인 프로젝트 Amego와는 별개의 서비스입니다.

02PROBLEM

어떤 문제가 있었나

리뷰 생성·재평가·삭제에 따라 장소의 점수를 다시 계산해야 했습니다. 큐를 통과한 이벤트의 ID를 복원하고 워커 종료 시 진행 중 작업을 다루는 흐름도 필요했습니다.

03CONSTRAINTS

무엇을 바꿀 수 없었나

서비스 이벤트와 별도 프로세스의 워커가 데이터를 주고받았습니다. 리뷰 변경뿐 아니라 연관 뱃지 부여·취소의 처리 순서와 트랜잭션 범위도 함께 다뤘습니다.

04ARCHITECTURE / DECISION

어떤 경계를 선택했나

리뷰 변경 이벤트를 점수 계산 큐에 넣고 독립 워커가 핸들러를 실행하도록 구성했습니다. 이벤트 직렬화·역직렬화에서 ID를 복원하고, 종료 시 진행 중 작업을 재등록하는 분기를 구현했습니다. 트랜잭션 표시가 있는 뱃지 부여·취소 서비스의 병렬 호출은 순차 await로 바꿨습니다.

05IMPLEMENTATION

어떤 책임을 구현했나

리뷰 생성·재평가·삭제 이벤트 핸들러, 점수 계산 큐 저장소와 독립 워커를 개발했습니다. 큐 이벤트의 직렬화·ID 복원과 워커 종료 처리를 수정하고, 연관 뱃지 처리의 호출 순서를 보완했습니다. 점수 계산 후처리의 ECS task/service 설정도 추가했습니다.

06RESULT

무엇이 확인됐나

리뷰 변경에서 큐·워커의 점수 계산으로 이어지는 처리 경로와 이벤트 복원, 종료 분기를 구현했습니다. 뱃지 부여·취소의 호출 순서를 수정하고 후처리용 ECS 설정을 추가했습니다.

07RETROSPECTIVE

무엇을 다시 고려하나

지금 다시 보면 큐를 사용하는 것과 모든 실패에서 작업 처리를 보장하는 것은 다른 문제입니다. 다음에는 작업의 완료 조건, 재등록·실패 처리와 이벤트 중복 검증을 함께 기록해 워커의 동작 범위를 더 명확히 남기고 싶습니다.
