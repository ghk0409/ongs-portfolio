01OVERVIEW

무엇을 만들었나

음원 추천 서비스에서 데이터 수집과 추천 데이터베이스 구조 설계, 사용자 상황과 음원 데이터에 따른 추천 기능 및 REST API 개발을 수행했습니다. 추천 DB 개편과 단계별 추천 개발은 서로 다른 시기의 작업이며, 이 사례에서는 데이터와 서비스 접점에 대한 담당 범위를 함께 소개합니다.

02PROBLEM

어떤 문제가 있었나

추천 데이터베이스 개편에서는 기존 진행 방식의 문제점을 정리하고 추천시스템의 요구사항에 맞게 데이터 구조를 설계할 필요가 있었습니다. 추천 기능 개발에서는 상황·감정·이용 패턴과 음원별 데이터를 서비스가 사용할 수 있는 기능별 인터페이스로 정의하는 작업이 필요했습니다.

03CONSTRAINTS

무엇을 바꿀 수 없었나

DB 구축에서는 데이터 크롤링과 구조 설정을 담당했고, 추천 기능은 별도의 2인 프로젝트에서 개발했습니다. 서로 다른 시기에 진행한 데이터 개편과 추천 기능 개발을 구분하면서, 데이터 준비와 서비스 API의 접점을 함께 다뤘습니다.

04ARCHITECTURE / DECISION

어떤 경계를 선택했나

추천 DB는 데이터 요구사항을 분석하고 ERD를 정리한 뒤 설계된 구조에 맞춰 데이터를 수집했습니다. 추천 기능은 상황·감정·이용 패턴·음원 유사도별로 구분하고 REST API 인터페이스를 정의했습니다. 음원 데이터의 유사도를 다루는 데 상관계수·코사인 유사도·Autoencoder를 활용했습니다.

05IMPLEMENTATION

어떤 책임을 구현했나

Selenium과 Requests를 이용한 크롤러 설계·수집과 MySQL DB화를 진행했습니다. 사용자 상황 예측, 입력된 감정·이용 패턴에 따른 추천, 음원·채널·태그·가사 등 데이터의 유사도를 활용한 추천 기능을 개발했습니다. 기능별 REST API 인터페이스를 정의하고 Flask 서버를 개발했습니다.

06RESULT

무엇이 확인됐나

추천에 필요한 데이터의 구조를 설계하고 수집·DB화를 진행했습니다. 별도의 추천 기능 개발에서는 기능별 REST API 인터페이스와 Flask 서버를 구현했습니다. 데이터 준비부터 서비스가 사용하는 API까지 이어지는 작업을 수행했습니다.

07RETROSPECTIVE

무엇을 다시 고려하나

지금 다시 보면 추천 경험은 모델 이름만으로 설명하기보다 어떤 데이터가 준비돼야 하고 서비스가 어떤 입력·출력을 사용하는지 함께 보여줘야 합니다. 다음에는 데이터 품질 점검과 모델 평가, API 동작 검증을 분리해서 기록하고, 실험 기능과 실제 적용 기능의 범위를 명확히 남기고 싶습니다.
