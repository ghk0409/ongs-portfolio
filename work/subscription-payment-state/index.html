예약 결제 변경과 실패 웹훅의 상태를 연결하기

카드 변경 뒤 예약 결과에 맞춰 구독·영수증 상태를 갱신하고, 결제 실패 웹훅에서 기록이 없는 경우의 처리와 환불 계산을 보완했습니다.

01OVERVIEW

무엇을 만들었나

구독·결제 서비스에서 API와 도메인 테스트를 개발하고, 카드 변경 뒤 예약 처리와 결제 실패 웹훅을 보완했습니다. 정산·계약 서비스와는 별도로 구독·영수증·예약 상태를 다룬 작업입니다.

02PROBLEM

어떤 문제가 있었나

카드를 변경한 뒤 신규 예약의 결과를 구독과 영수증 상태에 반영해야 했습니다. 예약 결제 실패 웹훅에서는 연관 영수증 기록을 찾지 못하는 경우도 처리해야 했습니다.

03CONSTRAINTS

무엇을 바꿀 수 없었나

외부 예약 요청의 결과와 내부 구독·영수증 상태를 함께 다뤘습니다. 예약 요청 처리와 후속 웹훅은 서로 다른 진입점이었으며, 실패 경로에서도 필요한 기록을 연결해야 했습니다.

04ARCHITECTURE / DECISION

어떤 경계를 선택했나

신규 예약 요청의 성공·실패에 따라 내부 상태 저장을 분기했습니다. 성공 시 예약 영수증과 다음 결제 상태를 연결하고, 실패 시 실패 상태를 저장한 뒤 오류를 반환했습니다. 실패 웹훅에서는 해당 예약 유형의 영수증이 없을 때 생성 경로를 호출하고, 끝내 연관 기록을 찾지 못하면 명시적인 오류를 반환하도록 보완했습니다.

05IMPLEMENTATION

어떤 책임을 구현했나

카드 변경 후 예약 결과에 따른 구독·영수증·다음 결제 상태 갱신을 추가했습니다. 실패 웹훅의 영수증 누락 처리와 오류 반환을 수정하고, 환불 계산의 일부 반올림 처리를 보완했습니다. 구독·영수증 등 결제 도메인의 테스트 코드도 추가했습니다.

06RESULT

무엇이 확인됐나

예약 결과와 내부 상태를 연결하는 성공·실패 분기, 영수증 기록이 없는 실패 웹훅의 보완 경로를 구현했습니다. 환불 계산의 반올림 처리를 수정하고 도메인 테스트를 추가했습니다.

07RETROSPECTIVE

무엇을 다시 고려하나

지금 다시 보면 외부 요청의 결과와 내부 업무 상태를 따로 확인할 수 있어야 합니다. 다음에는 웹훅 중복·순서 변경, 예약 변경 실패의 검증 기록을 함께 남겨 구현한 분기와 처리 보장의 범위를 더 명확하게 설명하고 싶습니다.
